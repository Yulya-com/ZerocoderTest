# Соглашения по веткам

Проект использует упрощённый Git Flow.

## Постоянные ветки

| Ветка | Назначение | Защита |
|---|---|---|
| `main` | Стабильная версия. Только проверенный код, который можно запускать. | Прямые коммиты не приветствуются |
| `develop` | Интеграционная ветка. Сюда сливается готовая работа перед релизом. | — |

## Временные ветки

| Шаблон | Для чего | Откуда | Куда сливается |
|---|---|---|---|
| `feature/<краткое-имя>` | Новая функциональность | `develop` | `develop` |
| `fix/<краткое-имя>` | Исправление ошибки | `develop` | `develop` |
| `docs/<краткое-имя>` | Документация | `develop` | `develop` |
| `release/<версия>` | Подготовка релиза | `develop` | `main` и `develop` |
| `hotfix/<версия>` | Срочная правка на проде | `main` | `main` и `develop` |

## Правила коммитов

Используется формат Conventional Commits:

```
<тип>: <краткое описание в повелительном наклонении>
```

Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`, `ci`.

Примеры:

```
feat: добавить команду /reset для сброса диалога
fix: обновлять токен GigaChat за 60 секунд до истечения
docs: описать переменные окружения в README
```

## Минимальный сценарий работы

```bash
git switch develop
git switch -c feature/my-feature
# ... правки ...
git add .
git commit -m "feat: ..."
git push -u origin feature/my-feature
# открыть Pull Request в develop, пройти CI, влить
```
